# Known Limitations and Future Work

## Agent Execution & Coordination

### 1. Sequential Multi-Agent Topology
Our current orchestrator runs a sequential pipeline: `Coder → Tester → Reviewer`.
This is a standard waterfall structure:
- It lacks **conversational back-and-forth** or negotiation between Tester and Coder.
- If the Reviewer rejects code, the orchestrator loops to Coder but without rich, multi-agent debate (e.g. peer review panels or consensus-based voting).

### 2. Lack of DAG Subtask Planning
While the orchestrator executes steps sequentially, it does not support breaking down a complex prompt into an arbitrary Directed Acyclic Graph (DAG) of subtasks to be run in parallel (e.g. running 3 sub-agent coders in parallel and merging their PRs).

---

## Memory & Retrieval (Episodic Store)

### 1. Hash-Collision Trigram Embeddings
Our `EpisodicStore` uses a 256-dimension character-trigram frequency vector mapped via `hash(trigram) % 256`.
- **Collisions**: Multiple distinct trigrams map to the same vector index.
- **No semantic understanding**: Cosine similarity is purely keyword-based (lexical) and does not capture synonym relationships (e.g., "calculate" vs "compute").
- To solve this, a production-grade agent requires dense embeddings generated by a pre-trained transformer model (e.g. `text-embedding-3-small` via OpenAI API) stored in a vector database (e.g. Chroma, pgvector).

### 2. Simple Rolling Window Memory
Our `ConversationBuffer` trims the oldest non-system messages. This loses long-term context:
- Key variables or constraints declared in message 2 are forgotten after 10 turns.
- Production systems use **summarisation-based memory compression** (where old turns are replaced with an LLM-generated summary paragraph) or hierarchical state tracking.

---

## Security (Sandbox execution)

### 1. Local Process Execution
`ShellExecuteTool` runs commands locally using Python's `subprocess.run()`. Even with a timeout:
- It has full access to the local file system (can read, write, delete any file accessible by the user).
- It runs with the user's OS privileges.
- Production sandbox environments MUST use isolated Docker containers (gVisor or Firecracker microVMs) to execute agent code safely without risking host compromise.

### 2. Simple AST evaluation
`PythonEvalTool` parses AST to block imports. It can still be bypassed using obfuscated methods (e.g. `getattr(getattr(str, '__class__'), '__subclasses__')()[...]` to navigate the object tree and access blocked builtins).
